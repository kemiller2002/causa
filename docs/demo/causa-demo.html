Causa

A workspace for causal investigations: record what was observed, propose hypotheses, weigh the evidence for and against each one, and keep every change as history in your own GitHub repository.

Built in one 420-minute window by Claude agents, working from a frozen requirements package, under a governed verification gate.

Live preview: causa.echelonfoundry.com · Code: github.com/kemiller2002/causa · Demo build f28fd9e (branch slice/SL-T20)

The application

2 / 8

What you can do

  • Connect to a GitHub data repository; the token stays in tab memory only
  • Browse the investigations: lifecycle, last activity and counts on each card
  • Open frozen catalog cases: Apollo 11, Apollo 1, Challenger, a light bulb
  • Start your own investigation, record observations and hypotheses, Save, reopen
  • Causal Analysis: each hypothesis with the evidence that supports or contradicts it

How it is made

  • F# compiled to .NET WebAssembly, written in a functional style: immutable data, pure functions, Result over exceptions
  • Limen 0.9.1 boundary, Forma 0.13 design tokens, phone-first layout
  • Storage: events in a GitHub repository (causa-storage 1.1.0 codec, RFC 8785 JSON)
  • Explicit state machines for save, conflict and load

The video that goes with this deck shows these flows at phone width (390 px).

How it was built with AI

3 / 8

From a frozen specification

  • Requirements package v4.1.6, frozen, in kemiller2002/Indy-init: 31 work items, a slice manifest and test identities
  • A requirements compiler turns it into obligations; the gate checks each one by its exact test identity
  • Nothing in the package, the lock or the owner records was edited by the agents

One coordinator, several agent lanes

  • A Claude coordinator plans the work, routes merges and owns the PRs
  • Lanes for integration, UI, domain and persistence, each in its own git worktree and slice/SL-… branch
  • One owner per file (agent-file-ownership.json); a change needed in someone else's file goes back as a request
  • The owner steered by chat; family feedback on a phone became fixes within the hour

Security

5 / 8

In the application

  • The token is kept only in the tab's memory and is never saved
  • A test checks that none of 22 fragments of the deploy token ever appears in the UI
  • The app talks only to https://api.github.com
  • Only the Limen capabilities in use ship; the build fails if a storage API is referenced

In delivery

  • The deploy scans the built site for credentials; a silent-exit bug under bash -e -o pipefail was fixed, with a test that runs the step verbatim
  • The gate's own token is read-only; live tests use short-lived app tokens, separate for read and write, revoked when the job ends
  • Agents kept to their sandbox: one denied workaround was reported, not retried

Delivery

6 / 8

Pipeline

  • On every PR: Verification gate, Causa CI, Build and test, Praxis validation, Echelon foundations
  • Merge commits only: green on the current head, up to date with main, never rebased or force-pushed
  • GitHub Pages deploy; /provenance.json names the exact commit served
